# VPN Hub Lite

Личный хаб на Cloudflare Workers: собирает серверы из источников, выдаёт каждому
человеку **персональную** ссылку-подписку для Happ, регистрирует людей через
Telegram-бота и распределяет их по серверам так, чтобы ноды не переполнялись.

Работает на бесплатном плане Cloudflare: без карты, без сервера, без Docker.

```
Telegram ──webhook──▶ Worker ──▶ D1 (данные)
                        │        KV (кэш подписок)
Happ ──GET /sub/<токен>─┘        cron: sync + health
```

## Лимиты бесплатного плана и как они учтены

Проверено по документации Cloudflare (Workers / KV / D1, разделы Limits):

| Ограничение | Значение | Что делает код |
|---|---|---|
| CPU на запрос и на cron | **10 мс** | разбор ограничен 120 ключами и 300 КБ; за прогон 2 источника и 8 серверов |
| Подзапросы (fetch, D1, KV) | **50 на вызов** | батчи по 25, не больше 30 сообщений в цикле, одна выборка на страницу |
| Одновременные соединения | **6** | TCP-проверки идут последовательно |
| Cron-триггеров на аккаунт | **5** | используется 3: sync, health и минутный опрос бота (см. ниже) |
| KV: записи | **1000/сутки** | подписка кэшируется на 600 с, источник — на 6 ч; `fetch_log` пишется не чаще раза в час на человека |
| KV: запись одного ключа | **1/с** | каждый ключ пишется один раз за TTL |
| D1: запросов на вызов | **50** | выборки точечные, вставки — батчами |
| D1: размер базы | **500 МБ** | журнал событий и `fetch_log` маленькие, чистятся вручную |

Если людей станет много, первым упрётся KV: при 100 активных подписках и
обновлении раз в 6 часов это ≈ 400 записей в сутки — запас есть. При 300+
подписках увеличьте `SUB_CACHE_TTL` до 1800.

# Установка с нуля

## Шаг 0. Что понадобится

- Аккаунт Cloudflare (бесплатный, **карта не нужна**).
- Telegram-аккаунт и бот от [@BotFather](https://t.me/BotFather).
- Node.js 18+ (лучше 20) — [nodejs.org](https://nodejs.org), кнопка LTS.
- 15–20 минут.

Проверка, что Node есть:

```bash
node -v      # v20.x или выше
npm -v
```

## Шаг 1. Регистрация в Cloudflare

1. Откройте https://dash.cloudflare.com/sign-up — email + пароль, карта не спрашивается.
2. Подтвердите почту.
3. Ничего покупать не нужно: Workers Free включён по умолчанию.

## Шаг 2. Wrangler

```bash
cd vpn-hub-lite
npm install
npx wrangler login
```

Откроется браузер — разрешите доступ. Проверка:

```bash
npx wrangler whoami
```

## Шаг 3. База D1 и кэш KV

```bash
npx wrangler d1 create vpn-hub-lite
```

В выводе будет `database_id = "xxxxxxxx-..."` — скопируйте его в
`wrangler.toml` вместо `REPLACE_WITH_D1_DATABASE_ID`.

```bash
npx wrangler kv namespace create CACHE
```

Скопируйте `id = "..."` в `wrangler.toml` вместо `REPLACE_WITH_KV_NAMESPACE_ID`.

> Если позже захотите preview-окружение, добавьте `preview_id` — для личного
> хаба это не нужно.

## Шаг 4. Секреты

Придумайте значения и выполните по одному (каждая команда спросит значение):

```bash
npx wrangler secret put BOT_TOKEN        # токен из @BotFather
npx wrangler secret put WEBHOOK_SECRET   # любая длинная строка, например: openssl rand -hex 24
npx wrangler secret put ADMIN_TOKEN      # токен входа в /admin
npx wrangler secret put SALT             # соль для хэшей IP/UA, не меняйте потом
```

`ADMIN_TG_ID` уже задан в `wrangler.toml` (8938447065). Если нужен другой —
`npx wrangler secret put ADMIN_TG_ID` (секрет важнее переменной).

Проверка списка:

```bash
npx wrangler secret list
```

## Шаг 5. Схема базы

```bash
npx wrangler d1 migrations apply vpn-hub-lite --remote
```

Спросит подтверждение — `y`. Проверка:

```bash
npx wrangler d1 execute vpn-hub-lite --remote --command "SELECT name FROM sqlite_master WHERE type='table'"
```

Должны быть: `users, sources, servers, pools, pool_servers, user_pools, assignments, events, fetch_log`.

## Шаг 6. Деплой

```bash
npx wrangler deploy
```

В выводе будет адрес вида `https://vpn-hub-lite.<ваш-поддомен>.workers.dev`.
Впишите его в `wrangler.toml` → `PUBLIC_BASE_URL` (без слэша на конце) и
задеплойте ещё раз:

```bash
npx wrangler deploy
```

### Короткое имя «Апельсинка» (зеркало)

Тот же код можно отдавать под именем `apelsinka` — ссылка подписки выглядит
как `https://apelsinka.<ваш-поддомен>.workers.dev/sub/<токен>`. Зеркало
делится той же D1 и KV, отдаёт то же содержимое байт-в-байт, но не имеет
секретов и cron: бот, синхронизация и проверки остаются на основном
воркере. Обе ссылки работают одновременно — менять их у пользователей не
нужно.

```bash
npm run deploy:apelsinka        # то же: npx wrangler deploy -c wrangler.apelsinka.toml
```

Когда появится свой домен (например, бесплатный `apelsinka.eu.org` после
одобрения заявки на eu.org), он вешается на воркер как Custom Domain в
панели Cloudflare, а старые `*.workers.dev`-ссылки продолжают работать.

Проверка:

```bash
curl https://vpn-hub-lite.<поддомен>.workers.dev/healthz
# ok
```

## Шаг 7. Подключение бота

### Вариант А: опрос (по умолчанию, работает всегда)

Telegram отказывается ставить вебхук на домены `*.workers.dev` — отвечает
`Bad Request: bad webhook: Failed to resolve host`. Это его ограничение, а не
ошибка деплоя (DNS при этом резолвится из любой точки).

Поэтому по умолчанию включён резервный транспорт: раз в минуту Worker сам
забирает обновления через `getUpdates` (третий cron-триггер), а смещение
хранит в таблице `bot_state`. Ничего настраивать не нужно — бот работает
сразу после деплоя.

Проверка: откройте `/admin` → «Проверить обновления». Должно быть
«Новых обновлений: 0» (или больше, если вы только что писали боту).

### Вариант Б: вебхук на своём домене

Если у вас есть домен в Cloudflare, вебхук надёжнее и не тратит cron:

1. В `wrangler.toml` добавьте маршрут:
   ```toml
   routes = [{ pattern = "hub.example.com/*", zone_name = "example.com" }]
   ```
2. Поставьте `PUBLIC_BASE_URL = "https://hub.example.com"` и
   `BOT_TRANSPORT = "webhook"`.
3. Уберите строку `"* * * * *"` из `crons` (опрос больше не нужен).
4. `npx wrangler deploy`, затем в админке нажмите
   **«Подключить бота (setWebhook)»**.

### Ручная установка вебхука (если кнопка недоступна)

```bash
curl "https://api.telegram.org/bot<BOT_TOKEN>/setWebhook" \
  -H "content-type: application/json" \
  -d '{"url":"https://vpn-hub-lite.<поддомен>.workers.dev/webhook","secret_token":"<WEBHOOK_SECRET>"}'
```

Ожидаемый ответ: `{"ok":true,"result":true,"description":"Webhook was set"}`.

Проверка:

```bash
curl "https://api.telegram.org/bot<BOT_TOKEN>/getWebhookInfo"
```

`last_error_message` быть не должно. Если есть `401` — не совпал
`WEBHOOK_SECRET`; если `404` — неверный URL.

## Шаг 8. Первый вход и первая ссылка

1. Откройте бота, отправьте `/start`. Придёт «заявка отправлена админу».
2. Админу (ID из `ADMIN_TG_ID`) придёт сообщение с кнопками
   **Одобрить 7 / Одобрить 30 / Отклонить**. Нажмите «Одобрить 30».
3. Бот пришлёт персональную ссылку `https://.../sub/<токен>` и инструкцию.
4. Серверов пока нет — добавьте ключи: в боте `/addkey`, затем отправьте
   `vless://...` (можно несколько строк) или ссылку на подписку.
5. Подождите до 6 часов (или запустите sync вручную, см. ниже) — серверы
   появятся, а человеку бот напишет «Серверы обновлены».

Проверить, что подписка отдаётся:

```bash
curl -s "https://vpn-hub-lite.<поддомен>.workers.dev/sub/<токен>" | base64 -d
```

Должны быть строки `vless://...` с названиями вида `Европа · VLESS Reality #1`.

## Шаг 9. Happ

1. Установите Happ (Android/iOS/Windows/macOS).
2. «+» → «Импорт по ссылке» (Add subscription).
3. Вставьте ссылку из бота → сохраните.
4. Выберите сервер и включите VPN.

Обновление — автоматически, раз в 6 часов (заголовок
`profile-update-interval`). Вручную — потянуть список вниз.

## Шаг 10. Админка

Откройте `https://<воркер>/admin`, введите `ADMIN_TOKEN`.
Разделы: Пользователи (одобрить/продлить/забанить), Серверы (загрузка в %),
Источники (сроки, трафик, «сделать приватным»), Журнал.

Ссылки и токены в таблицах замаскированы — полностью видны по клику на
«ссылка».

# Если не работает

| Симптом | Причина | Что делать |
|---|---|---|
| `Error 1102 Worker exceeded resource limits` | превышен CPU (10 мс) | уменьшите `MAX_KEYS`/`BATCH` в `sync.ts` и `health.ts`, проверьте размер источника |
| `D1_ERROR: no such table` | не применены миграции | `wrangler d1 migrations apply vpn-hub-lite --remote` |
| `KV PUT failed: 429` | исчерпаны 1000 записей в сутки | поднимите `SUB_CACHE_TTL` до 1800–3600 |
| Бот молчит | не тот транспорт или бот не запущен | `/admin` → «Проверить обновления»; проверьте `BOT_TRANSPORT` (`polling` для workers.dev) |
| `bad webhook: Failed to resolve host` | Telegram не принимает `*.workers.dev` | оставьте `BOT_TRANSPORT="polling"` или подключите свой домен |
| Ответ на вебхук `403` | заголовок не совпал с `WEBHOOK_SECRET` | перевыпустите секрет и `setWebhook` заново |
| В `/sub` заглушка «Срок истёк» | статус или дата | `/extend <tg_id> 30` |
| В подписке нет серверов | нет назначений или все мертвы | `/servers`, `/rebalance`, `/grant`; проверьте пулы |
| Сайт `1016` / `522` | неверный домен или воркер удалён | `wrangler deploy`, проверьте URL |
| Cron не срабатывает | триггеры появляются только после деплоя | `wrangler deploy`, затем `wrangler tail --format pretty` |

Логи в реальном времени:

```bash
npx wrangler tail --format pretty
```

Полезные запросы к базе:

```bash
npx wrangler d1 execute vpn-hub-lite --remote --command "SELECT id, tg_id, status, expires_at FROM users"
npx wrangler d1 execute vpn-hub-lite --remote --command "SELECT status, COUNT(*) FROM servers GROUP BY status"
npx wrangler d1 execute vpn-hub-lite --remote --command "SELECT id, name, kind, visibility, status FROM sources"
```

# Безопасность

- Все секреты — только `wrangler secret`; в репозитории их нет.
- `sub_token` — 32 случайных байта, сравнение за постоянное время.
- IP и User-Agent хранятся как `SHA-256(соль + значение)`, обрезанные до 32 символов.
- Кроме Telegram ID и username персональных данных нет.
- `/sub` ограничен 60 запросами в минуту с адреса, `/admin/login` — 5 попыток за 10 минут.
- Cookie админки: `HttpOnly; Secure; SameSite=Strict`, подписана HMAC от `ADMIN_TOKEN`.
- Полные ключи не логируются: в журнал и админку попадают только маски.
- `paid_private` и `visibility=private` не отдаются никогда — два уровня защиты
  (SQL-фильтр и `isDeliverable`) плюс тест.


## Вид платного сервиса и живучесть подписки

Две вещи, которые человек замечает раньше всего: как выглядит карточка подписки
в клиенте и не пропадают ли серверы через день.

### Карточка в клиенте

Заголовки ответа `/sub/<токен>` собирает `src/premium.ts`:

| Заголовок | Что даёт |
|---|---|
| `profile-title` | имя профиля `⚡ APELSINKA PREMIUM` вместо пустого списка |
| `profile-web-page-url` | кнопка «страница сервиса» в Happ |
| `support-url` | кнопка поддержки → бот из `BOT_USERNAME` |
| `profile-update-interval` | клиент сам перечитывает подписку раз в час |
| `subscription-userinfo` | объём и срок тарифа вместо «0 Б / 0 Б» |

Если в базе у человека заданы `traffic_gb` и `expires_at`, показываются они.
Если пусто — подставляется тариф по умолчанию: `PREMIUM_TRAFFIC_GB` (500 ГБ) и
`PREMIUM_PLAN_DAYS` (365 дней). Отключить подстановку: `PREMIUM_LOOK = "0"`.

Имена узлов собираются из страны, города, задержки и короткого протокола:
`🇫🇮 Финляндия · 339 мс · VLESS Reality`. Задержка — настоящий замер через
туннель; если замера нет, число не выдумывается. Верхушка списка получает одну
метку (`⚡ быстрый` или `🎮`), а не две сразу.

### Страница сервиса

`/` отдаёт тёмный лендинг из `src/landing.ts`: тариф, три свойства сервиса,
кнопка «Получить доступ» и ссылка на `/status`. Цифры на странице берутся из
того же окружения, что и заголовки подписки, — расхождений нет.

### Почему подписка не «умирает»

| Механизм | Что делает |
|---|---|
| резервный снимок | последняя удачная выдача хранится 7 суток, а не сутки |
| цепочка отката | при сбое сборки отдаётся `snapshot:<режим>`, затем `snapshot:default` |
| пустой список | заглушка отправляется только если резерва нет вообще |
| сторож пула | каждый тик считает проверенные узлы, пишет `pool:health` |
| тревога админу | ниже `POOL_MIN` (40) — сообщение в Telegram, не чаще раза в час |
| автоспасание | при просадке пула сборка источников запускается сразу, не чаще раза в час |

Сторож и автоспасание работают в тике `*/20 * * * *`: просадка замечается в
течение 20 минут, а не к следующей плановой сборке через 6 часов.

Проверить вручную:

```bash
npx wrangler d1 execute vpn-hub-lite --remote \
  --command "SELECT COUNT(*) FROM servers WHERE status='alive' AND verified_latency_ms>0"
npx wrangler tail --format pretty   # строки pool / sync
```

## Проверка Xray без домашнего компьютера

Раньше `tools/agent/verify.mjs` крутился локально по Планировщику задач Windows:
выключил ПК — пул не обновляется, мёртвые узлы остаются в подписке.

Теперь тот же агент запускается на раннере GitHub Actions
(`.github/workflows/verify.yml`), каждые 30 минут:

1. скачивает официальный Xray закреплённой версии и сверяет sha256;
2. берёт очередь `GET /api/checks/queue?served=1` (те узлы, что прямо сейчас
   попадают в подписку);
3. поднимает Xray на каждый узел и прогоняет через него настоящий запрос;
4. отправляет результаты `POST /api/checks`.

Репозиторий публичный, поэтому минуты Actions не тарифицируются.

Чтобы проверки не упирались в суточный лимит D1: очередь агента кэшируется
в KV на 90 секунд (параллельные прогоны не сканируют таблицу дважды),
агрегаты `/status` — на минуту, а сам агент запускается раз в 30 минут.
Узлы внешних подписок проверяются отдельным workflow `merge-check.yml`
и вообще не читают D1.

Что нужно один раз:

```bash
# секрет уже задан; если перевыпускаете токен — продублировать:
gh secret set CHECK_TOKEN --repo kot53094-creator/vless-sub

# ручной прогон
gh workflow run verify.yml
gh run list --workflow=verify.yml --limit 3
```

Локальный Планировщик после этого можно отключить: два агента одновременно
не нужны, они делят одну очередь и мешают друг другу считать «давно не
проверяли».

> Пуш файла workflow требует у `gh` области `workflow`:
> `gh auth refresh -s workflow`.

## ИИ-админ в боте

Бесплатная модель Workers AI (`@cf/meta/llama-3.3-70b-instruct-fp8-fast`,
10 000 нейронов в сутки) разбирает фразу админа и превращает её в действие.

```
/ai что с серверами?
/ai убери упавшие
/ai перераспредели людей с мёртвых
/ai вот ключ vless://...
/ai добавь источник https://example.com/sub.txt
/ai продли 123456789 на 30 дней
```

| Особенность | Как сделано |
|---|---|
| ключи и ссылки | распознаются без модели — LLM не переписывает UUID |
| изменения данных | только после `/ai да` (или `/ai нет`) |
| чужие команды | `/ai` отвечает только админу из `ADMIN_TG_ID` |
| нет доступа к AI | остальные команды работают, `/ai` пишет «модель недоступна» |
| журнал | каждое действие пишется в `events` |

Действия: `stats`, `list_dead`, `report`, `rebalance`, `sync`, `mark_dead`,
`add_key`, `add_source`, `extend_user`, `ban_user`, `topup_user`.

Для скриптов есть HTTP-вариант с тем же обработчиком:

```bash
curl -s -X POST https://vpn-hub-lite.twistx-launcher.workers.dev/api/ai \
  -H "x-check-token: $CHECK_TOKEN" -H "content-type: application/json" \
  -d '{"text":"что с серверами?"}'
# {"reply":"Сводка: узлов всего: 2790, ..."}

curl -s https://vpn-hub-lite.twistx-launcher.workers.dev/api/ai \
  -H "x-check-token: $CHECK_TOKEN"     # диагностика биндинга AI
```

## Ежедневный бэкап базы

D1 живёт в одном аккаунте: ошибка в миграции или случайный `DELETE` уносит
людей, ключи и назначения. `wrangler d1 export` требует запуска с ПК, а ПК
выключен большую часть суток, поэтому дамп собирается воркером.

- крон `0 4 * * *` — раз в сутки;
- содержимое: `settings, sources, pools, servers, pool_servers, users,
  user_pools, user_sources, assignments, promos, accruals`;
- формат: один JSON-файл, уходит документом в личный чат `ADMIN_TG_ID`;
- повторный запуск в тот же день пропускается (флаг `backup:<дата>` в KV);
- объём на 2026-11-02: **12 691 строка, 2.7 МБ**.

Ручной запуск и проверка доставки:

```bash
curl -s -X POST https://vpn-hub-lite.twistx-launcher.workers.dev/api/backup \
  -H "x-check-token: $CHECK_TOKEN"
# {"ok":true,"rows":12691,"bytes":2691493}
```

Файл содержит ссылки и токены подписки — без них восстановление бессмысленно,
поэтому он уходит только админу и не публикуется. Восстановление — импортом
таблиц в чистую базу.

## Скорость в подписи узлов

Агент проверки замеряет не только задержку, но и скорость скачивания через
туннель (`speed_mbps`). Для закреплённой верхушки списка протокол в имени
заменяется на реальный замер:

```
🇸🇪 Швеция Stockholm · 328 мс · ⚡ 9 Мбит/с · 🎮
🇫🇮 Финляндия · 361 мс · VLESS Reality        (замера нет — врать не будем)
```

Порог показа — 5 Мбит/с; ниже метка остаётся словесной (`⚡ быстрый`).

## Автопоиск источников и карантин

Раз в сутки (`30 3 * * *`) воркер проверяет короткий список публичных
подписок и добавляет новые в базу сам. Список — конкретные репозитории
(`src/discover.ts`), а не поиск по интернету: случайные ссылки проверить
нельзя.

Карантин — новый флаг `sources.quarantine`:

| Состояние | Что происходит |
|---|---|
| `1` (новый источник) | sync разбирает его, узлы ложатся в базу с `enabled = 0` |
| проверка | агент на GitHub Actions гоняет трафик через эти узлы |
| `0` (снят) | три узла прошли проверку за 72 ч → узлы включаются, источник в пуле |

Пока флаг стоит, узлы источника физически не могут попасть в подписку:
вся выдача фильтрует `servers.enabled = 1`.

```bash
# ручной прогон
curl -s -X POST https://vpn-hub-lite.twistx-launcher.workers.dev/api/discover \
  -H "x-check-token: $CHECK_TOKEN"
# {"added":["auto · barry-far/Sub1 (493)", ...],"skipped":1,"failed":[],"promoted":[]}
```

О добавлении и снятии карантина бот пишет админу. Отключить автопоиск —
удалить `discover` из `crons` в `wrangler.toml`.

## Бонусы, промокоды, баннеры, группы

Добавлено поверх базовой схемы (миграция `0006_bonuses.sql`).

| Файл | Назначение |
|---|---|
| `src/promotions.ts` | чистые функции: сутки по Москве, серии, потолки, коды (покрыты тестами) |
| `src/bonus.ts` | начисления, ежедневный бонус, рефералы, промокоды, группы, журнал |
| `src/banners.ts` | баннеры экранов: KV + `file_id` в D1, редактирование сообщений |
| `src/notify.ts` | уведомления о сроке и возврате, дедупликация через `notify_log` |
| `src/remnawave.ts` | клиент Remnawave (no-op, пока не заданы `REMNAWAVE_URL`/`REMNAWAVE_TOKEN`) |

### Как это работает

- **Идемпотентность.** Любое начисление пишется в `accruals` с уникальным `ref`
  (`daily:<id>:<дата>`, `channel:<id>`, `ref:i:<id>`, `promo:<код>:<id>`).
  Повторный вызов `INSERT OR IGNORE` не даёт второй награды — проверено на живой D1.
- **Ежедневный бонус.** Один раз в сутки по Москве (сброс 00:00), серия растёт,
  на 3-й день и каждый 7-й — повышенный бонус, месячный потолок обрезает начисление.
- **Рефералы.** `t.me/<bot>?start=ref_<код>`; награда обоим в момент первой
  активации приглашённого, с месячным потолком для пригласившего.
- **Промокоды.** `/promo КОД` или кнопка в кабинете; дни, часы, ГБ, группа Bypass.
  Общий лимит и лимит на пользователя, срок действия, защита от гонки.
- **Группы.** `Default` и `Bypass`; в админке раздел «Группы» привязывает squad
  к пулу серверов (`settings.squad_pool:<squad>`).
- **Баннеры.** 7 экранов; PNG лежат в KV (`banner:<key>`), после первой отправки
  используется `file_id`. Загрузка и предпросмотр — в админке.

### Команды

```
/promo КОД      активировать промокод
/bonus          забрать бонус дня
/ref            реферальная ссылка
```

### Админка

`/admin/bonuses` — все числа бонусов и уведомлений, кнопка ручного прогона.
`/admin/promos` — создание и выключение кодов.
`/admin/accruals` — журнал начислений с отменой.
`/admin/banners` — загрузка PNG и проверка отправки в Telegram.
`/admin/squads` — привязка групп к пулам, выдача и снятие.
