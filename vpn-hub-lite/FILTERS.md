# Фильтры подписки: как узел попадает в список

Документ описывает фактические правила, которые применяются в коде. Всё, что
не проходит хотя бы один фильтр, в подписку не попадает.

## 1. Отбор в пул (сборка снимка)

Снимок собирается из базы раз в час и живёт в KV. Условия для свободных узлов:

| Условие | Значение | Зачем |
|---|---|---|
| `enabled` | `= 1` | выключенные вручную не берём |
| `status` | `= 'alive'` | узел с проваленной проверкой уходит сразу |
| `country_code` | не пустой | иначе в клиенте вместо названия светится домен |
| `verified_latency_ms` | `> 0` | есть подтверждённый туннель, а не только открытый порт |
| `verified_at` | не старше 24 ч | сутки — потому что выданные узлы проверяются первыми |
| `blocked_ok` | `NULL` или `1` | узел, который режет Telegram, бесполезен |
| источник `visibility` | `shareable` | приватные источники в общий пул не идут |
| `share_until` | пусто или в будущем | истёкший доступ отсекается |
| имя источника | не содержит «Премиум» | премиум идёт отдельной веткой |

Сортировка: сначала проверенные за последние сутки, внутри — по возрастанию
задержки. Лимит — 60 узлов.

Премиум-ветка собирается отдельно: `tier = 'premium'`, `enabled = 1`, страна
заполнена, `blocked_ok` не `0`, лимит 40.

## 2. Фильтры при выдаче

Применяются на обоих путях — и через пул, и через назначения:

- **Заглушки.** Строки с подписью «Премиум сервер» и `tier != 'premium'`
  отбрасываются.
- **Выключенные.** `enabled = 0` не выдаётся.
- **Страна.** Без страны узел не показываем (кроме премиум-ветки).
- **Свежесть и живость.** `isWorkingServer` с окном 24 часа: подтверждение
  туннеля, свежая дата, `blocked_ok`.
- **Мёртвые.** `status = 'dead'` не выдаётся.
- **Российские выходы.** Узлы с российским флагом исключаются из выдачи.
- **Дубли.** Повторяющиеся метки нумеруются (`#2`, `#3`), одинаковые конфиги
  схлопываются по ключу `uuid + хвост ссылки`.

## 3. Как узел проверяется

Агент запускается локально раз в час, берёт 100 узлов и поднимает Xray на
каждый.

| Шаг | Что делает | Результат |
|---|---|---|
| Туннель | HTTPS-запрос `204`, при сбое — HTTP `204`, две попытки | живость и задержка |
| Выходной IP | запрос `/api/ip` через туннель | нужен для определения «включён ли VPN» |
| Telegram | TCP до `149.154.167.51:443` | `blocked_ok` |
| Discord | TCP до `162.159.128.233:443` | `blocked_ok` |

Правила вердикта:

- **Два провала подряд** → `status = 'dead'`, отметка о проверке стирается.
- **Провал на gRPC / XHTTP** → мягкий провал: `status = 'unknown'`, узел не
  убивается, потому что пробник эти транспорты не пробивает достоверно.
- **Первый провал** → узел остаётся, но из пула выпадает: там требуется
  `status = 'alive'`.

## 4. Очередь проверок

Порядок очереди решает, обновится ли список вообще.

1. Узлы, которые уже выдаются (`verified_latency_ms > 0`).
2. Узлы с неизвестным выходным IP, выданные людям, если их не проверяли
   последние 30 минут.
3. Остальные — по давности проверки.

Раньше первыми бесконечно шли выданные узлы без выходного IP. Если такой узел
стабильно не отвечал, он каждый раз занимал начало очереди, и до остальных
дело не доходило.

## 5. Кэши

| Что | Где | Сколько живёт |
|---|---|---|
| Снимок пула | KV `pool:verified:v2` | 1 час |
| Премиум-снимок | KV `pool:verified:premium:v2` | 1 час |
| Тело подписки | KV `sub:v55:<token>` | 10 минут |
| Аварийный снимок | KV `snapshot:default` | 24 часа, только при сбое базы |

## 6. Обход белых списков

Белый список — режим, когда провайдер пропускает только разрешённые ресурсы.
Обход строится из двух частей:

**Туннель.** Всё, что не входит в белый список, уходит в VPN. В профиле
`RU Direct v2` стоит `GlobalProxy: true` и пустой `ProxySites` — значит по
умолчанию через туннель идёт всё.

**Прямые маршруты.** Разрешённые сервисы идут напрямую, чтобы не ломаться:
`domain:ru`, `domain:su`, `geosite:category-ru` плюс 41 домен из белого списка
(банки, госуслуги, операторы, маркетплейсы, VK, Яндекс, MAX, Rutube).

**Требование к узлу.** Узел обязан открывать TCP до дата-центра Telegram.
Именно эта проверка отсеивает выходы, которые числятся живыми, но не обходят
блокировки.

## 7. Что фильтры не ловят

- Узел, который отдаёт `204`, но режет конкретный сервис по DPI. Проверка
  Телеграма покрывает главный случай, остальные — нет.
- Медленный узел. Порог есть (800 мс; для личного ключа eclvpn — 1100 мс,
  потому что его geo-entry узлы ходят через цепочку), но задержка ниже порога
  только сортирует список и ничего не обещает по скорости канала.
- Узел, умерший между проверками. Он исчезнет со следующей, то есть в течение
  суток — быстрее не получится при текущем объёме.
