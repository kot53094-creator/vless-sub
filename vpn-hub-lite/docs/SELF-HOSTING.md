# Свой сервер: что переносится, а что нет

Короткий ответ: **данные и код переносятся, платформенные сервисы — нет.**
Ниже конкретно, что именно придётся заменить и что уже проверено.

## Что нельзя перенести как есть

| Компонент | Почему | Что делать |
|---|---|---|
| `env.DB` (D1) | привязка Cloudflare | заменяется на SQLite/libSQL — **сделано** (`runtime/node/sqlite_shim.mjs`) |
| `env.CACHE` (KV) | другого провайдера с тем же API нет | таблица `kv_cache` в той же базе — **сделано** |
| `env.AI` (Workers AI) | модель живёт только в Cloudflare | отключается; команда `/ai` работает в облаке |
| `scheduled()` (cron) | триггеры Cloudflare | системный планировщик или cron-контейнер — **сделано** (`--cron`) |
| `cloudflare:sockets` | встроенный TCP-модуль | `node:net` — **сделано** (`shims/cloudflare_sockets.cjs`) |
| Секреты | экспорт секретов запрещён платформой | вводятся заново в окружение нового хоста |
| Telegram webhook | нужен публичный HTTPS | обратный прокси с сертификатом либо polling |

Отдельно: **VPN-узлы** к платформе не относятся. Они живут на собственных
серверах, и перенос панели их не касается.

## Запуск

```bash
cd vpn-hub-lite
npm run runtime:build      # tsc → runtime/node/build
npm run runtime:migrate    # схема в runtime/node/data.sqlite
npm run runtime:demo       # 1 источник, 1 узел, 1 человек (тестовые)
npm run runtime:serve      # http://127.0.0.1:8788
```

Проверка без сервера:

```bash
node runtime/node/smoke.mjs /healthz
node runtime/node/smoke.mjs /sub/<токен>
```

Секреты берутся из окружения или `.dev.vars`. База — `DB_FILE`
(по умолчанию `runtime/node/data.sqlite`).

## Что нужно для боевого запуска на своём сервере

1. **Процесс.** `node runtime/node/main.mjs` под systemd/pm2/Docker с
   автоперезапуском.
2. **HTTPS.** Обратный прокси (Caddy/nginx) — иначе Telegram не примет
   webhook. Альтернатива: `BOT_TRANSPORT=polling`, тогда публичный адрес не
   нужен.
3. **Cron.** Пять расписаний из `wrangler.toml` переносятся в crontab:
   ```
   0 6 * * *        node runtime/node/main.mjs --cron "0 6 * * *"
   ```
   Каждое расписание — отдельный вызов; состояние между вызовами в базе.
4. **Кэш.** KV-таблица растёт; раз в сутки чистить просроченные ключи
   (`DELETE FROM kv_cache WHERE expires_at IS NOT NULL AND expires_at <= ...`).
5. **Бэкап.** `sqlite3 data.sqlite ".backup backup.sqlite"` по cron плюс
   существующий `/api/backup` в Telegram.

## Ограничения этого варианта

- **Один процесс = одна база.** При нескольких инстансах SQLite на сетевом
  диске нельзя; нужен libSQL/Turso или Postgres.
- **Workers AI недоступен.** Команды `/ai` и автодиагностика требуют облака
  или внешнего API-ключа.
- **Гео и проверки** работают: TCP-проверки идут через `node:net`, страна —
  через HTTP-геосервис.
- **Масштаб.** SQLite держит сотни запросов в секунду на чтение; для тысяч
  пользователей нужен сервер с Postgres. Это не «бесплатно и без лимитов», а
  «свой сервер со своими лимитами».
- **Код не переписан.** Это тот же `src/`, собранный tsc; расхождения
  платформы изолированы в `runtime/node/`.

## Что осталось сделать для полноценного переезда

| Задача | Состояние |
|---|---|
| Экспорт данных из D1/Turso | готово (`/api/export`, `tools/portable-export.mjs`) |
| Запуск кода вне Cloudflare | готово, проверено |
| Поддержка Postgres | нет: нужен адаптер диалекта и Hyperdrive/HTTP-драйвер |
| Несколько инстансов | нет: нужен общий libSQL/Postgres |
| Workers AI вне облака | нет: нужен внешний провайдер модели |
