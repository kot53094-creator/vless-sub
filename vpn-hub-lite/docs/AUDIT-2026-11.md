## 2. Что реально исполняется

```
Telegram ──webhook/polling──▶ Worker (index.ts)
                               ├─ D1  (users, servers, plans, payments…)
                               ├─ KV  (кэш подписок, пул источников, снимки)
                               ├─ Workers AI (/ai, llama-3.3-70b)
                               └─ cron: sync / health / backup / discover
Happ, INCY, v2rayNG ──GET /sub/<токен>──▶ Worker
GitHub Actions ──Xray──▶ /api/checks, /api/merge/results
```

Cron-триггеров пять — это ровно лимит бесплатного плана:

| Расписание | Что делает |
|---|---|
| `0 */6 * * *` | синхронизация источников → серверы |
| `*/20 * * * *` | TCP-проверка партии + синхронизация внешних подписок с гейтом 30 мин |
| `0 4 * * *` | дамп базы в Telegram админу |
| `10 0 * * *` | автопоиск источников, карантин |
| `* * * * *` | резервный транспорт бота (polling) |

- Точка входа: `src/bot/index.ts`, обработчики разделены на

## 5. Состояние продакшена на 2026-11-11

| Проверка | Результат |
|---|---|
| `GET /healthz` | `ok` |
| `GET /api/v1/status` | **503** `db_unavailable` |
| `GET /status` | «База данных недоступна», 0 конфигураций, 0 источников |
| `GET /sub/<несуществующий токен>` | 200, заглушка «Подписка не найдена» (корректно) |
| Три источника подписок | 200, но тело — заглушка `vless://00000000-…@0.0.0.0:1#App not supported` |

Точная причина отказа D1 без панели Cloudflare не определяется: ответ
воркера говорит «лимит D1 или сбой». Это может быть суточная квота
(5 млн строк чтения), неудачная миграция или сбой биндинга. Диагностика —
первый шаг этапа 4.

Косвенное подтверждение квоты есть в самом коде: комментарий в
`src/health.ts` (строка 91) фиксирует, что прежний `ORDER BY` с
подзапросом `EXISTS` перечитывал все включённые узлы на каждом тике и
«именно это и съедало суточную квоту D1 (5 млн строк)». Сейчас там курсор
по первичному ключу и батч, то есть причина устранена, но накопленный
расход и текущее состояние биндинга всё равно нужно проверить в панели.

Источники при этом валидны: `subscription-userinfo` отдаёт реальный расход
и срок. Значит, панели не признают устройство (HWID), а не «умерли».
