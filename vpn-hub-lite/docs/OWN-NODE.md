# Свой узел: ключ, квота и срок под нашим контролем

Документ отвечает на вопрос «можно ли поставить чужие серверы за свой VPS,
чтобы ключ зависел от нас». Короткий ответ: да, технически это работает,
и код уже готов. Ниже — как именно и что при этом ломается.

## Зачем вообще свой узел

Пока подписка состоит из чужих узлов, у нас нет трёх вещей:

| Что нужно | Почему нельзя без своего узла |
|---|---|
| Отозвать ключ | UUID принадлежит владельцу сервера. Мы можем только перестать отдавать ссылку — у человека она уже сохранена в клиенте |
| Считать трафик | Поток идёт телефон → чужой сервер. Воркер видит только выдачу списка, а не байты |
| Ограничить срок | Срок в базе есть, но узел о нём не знает: подключиться можно сколько угодно долго |

Свой узел добавляет одну точку, через которую проходит весь трафик клиента,
и она наша.

## Схема

```
клиент ──REALITY(наш ключ)──► наш VPS ──► чужие vless-узлы (цепочка)
                                  │
                                  ├─ Xray API: счётчики по каждому ключу
                                  ├─ node-sync.mjs  (раз в 2 мин)  ← /api/node/clients
                                  └─ traffic-agent.mjs (раз в 5 мин) → /api/traffic
```

- Ключ клиента (UUID) выводится из его `sub_token` через HMAC-SHA256 с солью
  (`uuidForToken`). Он не хранится в базе, но всегда один и тот же — и его
  невозможно получить, зная только ссылку подписки.
- `email` клиента в конфиге Xray равен `sub_token`: по нему Xray считает
  байты, а панель понимает, чей это расход.
- Раз в 2 минуты узел забирает `/api/node/clients`. Тех, у кого истёк срок,
  кончился трафик или аккаунт заблокирован, сервер сам убирает из конфига.
  Даже с сохранённым профилем в клиенте человек не подключится.
- Раз в 5 минут `traffic-agent.mjs` отправляет дельты в `/api/traffic`, и в
  кабинете начинают двигаться настоящие цифры. По исчерпании квоты выдача
  подписки отдаёт заглушку (это уже реализовано и покрыто тестами).

## Установка (Ubuntu 22.04/24.04, Debian 12)

```bash
# на VPS, права root
sudo PANEL_URL=https://vpn-hub-lite.twistx-launcher.workers.dev \
     CHECK_TOKEN=<токен агента проверок> \
     NODE_NAME="🇷🇺 Россия · свой" \
     UPSTREAMS=/root/upstreams.txt \
     bash relay-node.sh
```

`UPSTREAMS` — файл со ссылками `vless://`, по одной в строке. Это узлы, через
которые наш сервер выпускает трафик (те самые чужие серверы из текущей
подписки). Если файла нет — узел работает напрямую: быстрее и стабильнее, но
выходной IP будет адресом VPS.

Скрипт ставит Xray, генерирует ключи REALITY, включает статистику по
пользователям, ставит `node-sync` и `traffic-agent` в cron, открывает порт,
включает BBR — и печатает готовые переменные для воркера:

```
NODE_HOST, NODE_PORT, NODE_PUBKEY, NODE_SID, NODE_SNI, NODE_NAME
```

После их добавления в Cloudflare (Settings → Variables) в подписке каждого
клиента первой строкой появляется его личная ссылка на наш узел, а остальные
серверы остаются ниже как резерв.

## Что важно понимать про цепочку через чужие узлы

1. **Скорость падает вдвое.** Трафик проходит через два хоста. Если у VPS
   канал 100 Мбит/с, а у донора 50 Мбит/с — реально будет ближе к 50, плюс
   задержка двух плеч.
2. **Чужой узел может исчезнуть в любой момент.** В текущем пуле из
   проверенных живых узлов часть умирает за сутки. Балансировщик `leastPing`
   переживёт смерть одного выхода, но если умрут все — наш узел останется без
   интернета, хотя ключ у людей будет рабочий.
3. **Это чужая полоса.** Публичные узлы раздают энтузиасты; качать через них
   чужие гигабайты и продавать их — нарушение их правил, и владелец вправе
   закрыть доступ (в том числе по IP нашего VPS). Для теста и для «своего
   ключа на первое время» это допустимо, для продажи — риск.
4. **Наш IP виден.** Если VPS в РФ и на него пожалуются, его адрес уйдёт в
   блокировки быстрее, чем чужие. Поэтому SNI/маскировка должны быть
   правдоподобными, а порт — 443.

## Что правильно для платного сервиса

Свой узел **без цепочки**: Xray на VPS с выходом напрямую (`freedom`), плюс
один-два зарубежных VPS как резервные выходы. Тогда:

- скорость ограничена только каналом VPS;
- трафик и срок считаются честно;
- ключ отзывается мгновенно;
- нет зависимости от чужих серверов.

Цепочка остаётся как аварийный режим, когда наш IP заблокировали, а менять
сервер некогда.

## Проверка, что всё живо

```bash
systemctl status xray --no-pager | head -n 5   # сервис поднят
ss -lntp | grep 443                            # порт слушается
tail -n 20 /opt/vpn/sync.log                   # сколько ключей синхронизировано
tail -n 20 /opt/vpn/agent.log                  # сколько трафика отправлено
curl -s -H "x-check-token: <токен>" https://<домен>/api/node/clients | head -c 300
```

В кабинете признак успеха — в блоке «Общий трафик» появляются реальные
проценты вместо надписи «учёт расхода не подключён».

## Если ключ нужно отозвать вручную

1. Блокировка аккаунта в админке (`status=banned`) — узел уберёт ключ в
   течение 2 минут.
2. Мгновенно: удалить строку из `clients` в конфиге и `systemctl restart xray`.
3. Токен подписки можно перевыпустить — тогда изменится и UUID, старый ключ
   перестанет работать навсегда.
