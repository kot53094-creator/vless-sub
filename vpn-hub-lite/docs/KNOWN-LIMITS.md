# Что не реализовано и почему

Список ведётся честно: если функции нет, она здесь, а не в разделе «готово».

## 1. Worker не проверяет туннель сам

Cloudflare Workers не запускают бинарники и не дают долгих процессов.
`connect()` из `cloudflare:sockets` открывает TCP-сокет, но не выполняет
VLESS-рукопожатие и REALITY.

Поэтому:

- `health.ts` проверяет только доступность порта (`kind='tcp'`);
- настоящая проверка — внешний Xray-агент (`kind='tunnel'`);
- рейтинг и режимы `working` / `best` / `stable` опираются только на туннель.

Пока агент не запускался, все серверы имеют `verified_at = null`, а
`stability = 0`. Это корректное состояние, а не ошибка.

## 2. Workflow GitHub Actions не загружен

`.github/workflows/verify.yml` существует локально, но не в репозитории:
токен GitHub без области `workflow`, а расширить её может только владелец
аккаунта в браузере. Инструкция — в [OPERATIONS.md](OPERATIONS.md), раздел 3.2.
До этого агент запускается локально.

## 3. Нет SPA на React

Спецификация предлагала React + Vite + Tailwind. Фактически интерфейс —
серверный HTML из Worker. Причины: не нужен второй деплой, нет CORS между
сайтом и API, страница открывается на слабом телефоне без загрузки бандла.
Функционально админка закрывает те же задачи, но визуально это не SPA.

## 4. Нет регистрации по email и восстановления пароля

Вход — только через Telegram. Почтового сервиса без карты, который можно
считать надёжным, в бюджет не заложено. Восстановление доступа — через
Telegram-аккаунт; если он потерян, помогает только админ вручную. Паролей
нет, поэтому и утечки паролей нет.

## 5. Нет платежей и тарифной оплаты

Есть категории `free` / `premium` / `personal` и лимиты, но нет платёжного
шлюза. По условию проекта карта не используется. Подключение оплаты —
отдельное решение владельца с проверкой законов и правил платформы.

## 6. Экспорт только в Base64-подписку

`/sub/<токен>` отдаёт формат, который понимает Happ. Экспорт в JSON,
Sing-box и Clash не реализован: без проверки совместимости на реальных
клиентах это была бы имитация. Добавлять — только вместе с тестами на
конкретных версиях клиентов.

## 7. Ограничения по чужим серверам

- порт менять на чужом сервере нельзя — только отображать и проверять;
- гарантий обхода блокировок нет: часть узлов недоступна из РФ, это
  показывают проверки;
- «100% рабочим» не называется ни один конфиг;
- источники могут отозвать ключи в любой момент.

## 8. Лимиты бесплатного плана

Реальные цифры и расчёт — в [FREE-LIMITS.md](FREE-LIMITS.md). Кратко:
100 000 запросов в сутки, 10 мс CPU, 50 подзапросов на вызов, 1 000 записей
KV в сутки. При росте аудитории первым упрётся KV-кэш подписок.

## 9. Незавершённые пункты спецификации

| Пункт | Состояние |
|---|---|
| Версии подписок и откат | сделано (`sub_versions`, страница «Версии подписок») |
| Статистика источников и причины отказа | сделано (`import_runs`, страница «Импорт») |
| Публичный API и OpenAPI | сделано (read-only, без секретов) |
| Страница состояния | сделано (`/status`) |
| Правило «два провала подряд» | сделано |
| Разделение TCP и туннельных проверок | сделано (`server_checks.kind`) |
| Экспорт JSON / Sing-box / Clash | не сделано, причина в п. 6 |
| Отчёт в Telegram по проверкам | частично: ежедневный дайджест есть, отчёт по туннелю — нет |
| Отдельная админ-страница устройств | частично: устройства видны в боте и в карточке пользователя |
| Автоматическая загрузка workflow | заблокировано правами GitHub |

## 10. Юридическая готовность

Проект не проверен юридически. Перед коммерческим использованием нужны:

- проверка условий источников конфигураций;
- пользовательское соглашение и политика конфиденциальности;
- порядок обработки жалоб правообладателей;
- проверка применимого законодательства о связи и персональных данных.

Ничего из этого в коде не заменяется «галочкой в интерфейсе».

## 11. Внешние подписки

- Импорт включается только с разрешения владельцев источников. Технически
  модуль умеет читать любой источник, но право на редистрибуцию проверяет
  человек, а не код.
- Панели источников ограничивают число устройств на HWID. Если лимит
  исчерпан, источник отдаёт заглушку — это видно в `/admin/merge`, но
  исправляется только на стороне владельца.
- Доступность узлов подтверждает только агент GitHub Actions. Без прогона
  узлы остаются «не проверенными» и выдаются в подписке без гарантии.
- Проверка xhttp/grpc через CDN может ложно провалиться (`soft`): такие узлы
  не помечаются мёртвыми, но и «рабочими» не считаются.
- Страна определяется по IP через внешние справочники. Для хостингов это
  обычно верно, для анонимных сетей — нет.
- Интерфейс INCY подписка не меняет: тема и режимы NORMAL / AUTO / SPLIT —
  настройки самого клиента.
