# Внешние подписки (объединённый список)

Модуль подмешивает узлы из разрешённых внешних подписок в основную подписку
«Апельсинка VPN». Ссылка подписки при этом не меняется: новые узлы появляются
в ней автоматически, а при сбое источника остаётся последняя рабочая версия.

## Что происходит

```
cron */20 (внутри — гейт 30 минут)
        │
        ▼
MERGE_SOURCE_A/B/C ──fetch──▶ разбор ответа ──▶ дедупликация
                                                  │
                                     KV merge:pool:v1
                                                  │
Happ ◀── /sub/<token> ◀── якоря + резерв + узлы источников
        /sub/<token>/auto  ◀── Xray-JSON с балансировщиком
        /sub/<token>/sb    ◀── sing-box с urltest
```

Дополнительные ключи в KV:

| Ключ | Что лежит |
|---|---|
| `merge:pool:v1` | последний рабочий список узлов (JSON) |
| `merge:status:v1` | время синка, статусы источников, счётчики |
| `merge:off:v1` | источники, выключенные в админке |
| `merge:geo:<host>` | кэш страны/города по адресу узла (30 дней) |

## Хранение секретов

Ссылки источников и HWID **никогда** не попадают в код, репозиторий и логи.
Только Cloudflare Secrets:

```bash
cd vpn-hub-lite
npx wrangler secret put MERGE_SOURCE_A
npx wrangler secret put MERGE_SOURCE_B
npx wrangler secret put MERGE_SOURCE_C
npx wrangler secret put MERGE_HWID
```

`MERGE_HWID` — идентификатор устройства, зарегистрированного у владельца
источника. Без него панели Remnawave отдают заглушку «App not supported»,
с чужим HWID — «Превышен лимит устройств».

Выключить подмешивание без удаления секретов:

```toml
# wrangler.toml
MERGE_ENABLED = "0"
```

или выключить конкретный источник в `/admin/merge`.

## Добавление источника

1. Получите у владельца источника письменное разрешение на импорт.
2. Убедитесь, что ссылка отдаёт данные для `Happ/2.9.1` и вашего HWID.
3. Запишите ссылку в свободный слот `MERGE_SOURCE_A/B/C`.
4. Нажмите «Синхронизировать сейчас» на `/admin/merge`.
5. Проверьте, что источник в статусе «работает» и отдал узлы.

Слоты фиксированы (A/B/C). Чтобы добавить четвёртый источник, нужно расширить
массив `SOURCES` в `src/merge.ts` и добавить поле в `Env`.

## Ручное обновление

- Админка: `/admin/merge` → «Синхронизировать сейчас».
- API:

```bash
curl -X POST -H "x-check-token: $CHECK_TOKEN" \
  https://vpn-hub-lite.twistx-launcher.workers.dev/api/merge/sync
```

Автосинхронизация встроена в cron `*/20 * * * *` с внутренним гейтом:
фактический запрос к источникам — не чаще раза в 30 минут. Отдельный
cron-триггер не заводится, на бесплатном плане их всего пять.

## Проверка узлов

Worker не умеет держать долгие TCP-соединения через Xray, поэтому доступность
проверяет агент GitHub Actions:

1. `GET /api/merge/pool` — список `{id, link}` (закрыт `CHECK_TOKEN`);
2. `tools/agent/verify.mjs` с `MERGE=1` поднимает Xray на каждый узел;
3. `POST /api/merge/results` — `{id, ok, latencyMs, soft}`.

Workflow: `.github/workflows/merge-check.yml`, каждые 2 часа. Ручной запуск —
`workflow_dispatch`.

Правила статусов:

- `ok` — узел реально пропустил трафик, попадает в подписку;
- `fail` — узел мёртв, из подписки исключается (остаётся в админке);
- `fail(soft)` — не прошёл транспорт (xhttp/grpc через CDN), остаётся
  «не проверенным» и из подписки не выкидывается.

Локальная проверка:

```powershell
cd vpn-hub-lite/tools/agent
$env:BASE_URL="https://vpn-hub-lite.twistx-launcher.workers.dev"
$env:CHECK_TOKEN=(Get-Content "$env:USERPROFILE\.vpn-check-token" -Raw).Trim()
$env:MERGE="1"
node verify.mjs "C:\path\to\xray.exe"
```

## Место в подписке

Порядок жёсткий:

1. закреплённые якоря (10 узлов golu-gulu) — всегда первые;
2. проверенный резерв из пула;
3. узлы внешних подписок;
4. «белый список» и прочее.

Дубли по паре `host:port` отбрасываются: узел источника не появится, если
такой адрес уже есть в подписке. Мёртвые узлы не выдаются.

## INCY и другие клиенты

Подписка — обычный VLESS-список (base64) плюс два JSON-профиля:

- `/sub/<token>/auto` — Xray-JSON с балансировщиком `leastPing`;
- `/sub/<token>/sb` — sing-box с `urltest`.

INCY импортирует VLESS-подписку как список серверов. **Интерфейс INCY от
подписки не меняется**: тёмно-зелёная/лаймовая тема — это оформление самого
клиента, а не результат импорта. Режимы NORMAL / AUTO / SPLIT в INCY
переключаются средствами клиента; подписка не может включить режим, который
клиент не поддерживает.

## Ошибки и что делать

| Симптом | Причина | Действие |
|---|---|---|
| «Превышен лимит устройств» | HWID занят другим устройством у владельца | попросить владельца освободить устройство |
| «App not supported» | нет/неверный `MERGE_HWID` или User-Agent | проверить `MERGE_HWID`, `FETCH_UA` |
| Источник «не настроен (нет секрета)» | пустой слот `MERGE_SOURCE_*` | добавить секрет |
| Источник «ошибка», узлы остались | источник не ответил | ничего: работает прошлая версия |
| Узел «не проверен» | агент ещё не прогнал проверку | дождаться workflow или запустить вручную |
| Пустой список узлов | все источники отдали заглушку | проверить секреты и лимит устройств |

## Ограничения

- Источники обязаны разрешать редистрибуцию; без разрешения импорт не
  включается.
- Панель может ограничивать число устройств на один HWID.
- Без агента GitHub Actions узлы остаются «не проверенными» — они выдаются,
  но их задержка и доступность не подтверждены.
- Гео определяется по IP через `ipwho.is` / `ip-api.com`; лимит — 12 новых
  запросов за синк, дальше используется кэш.
- Объединённый список живёт в KV, а не в D1: суточная квота D1 не должна
  ронять подписку.
