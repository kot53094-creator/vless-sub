# Бесплатные лимиты и бюджет проекта

Все цифры взяты из официальной документации Cloudflare **23 октября 2026**.
Ни один из перечисленных сервисов не требует банковскую карту на бесплатном
плане. Платные функции не являются обязательной зависимостью.

Источники:

- Workers Limits — <https://developers.cloudflare.com/workers/platform/limits/> (обновлено 12.10.2026)
- D1 Pricing — <https://developers.cloudflare.com/d1/platform/pricing/>
- D1 Limits — <https://developers.cloudflare.com/d1/platform/limits/> (обновлено 21.04.2026)
- KV Limits — <https://developers.cloudflare.com/kv/platform/limits/> (обновлено 08.10.2026)
- Changelog: D1 начал жёстко применять суточные лимиты — <https://developers.cloudflare.com/changelog/post/2026-09-01-d1-free-tier-limit-enforcement/>

## Workers (Free)

| Параметр | Лимит | Как учтено в проекте |
|---|---|---|
| Запросы | 100 000 / сутки | подписка кэшируется на 600 с, страницы админки не опрашиваются автоматически |
| CPU на запрос и cron | 10 мс | разбор ≤ 120 ключей, ≤ 300 КБ, 2 источника за прогон |
| Подзапросы (fetch, D1, KV) | 50 на вызов | батчи по 25, приём проверок ≤ 20 результатов за POST |
| Одновременные соединения | 6 | TCP-проверки последовательные |
| Cron-триггеров | 5 на аккаунт | занято 3 |
| Размер Worker | 64 MiB | текущая сборка — единицы МБ |
| Память | 128 МБ | не держим большие тела в памяти |

При исчерпании суточного лимита Cloudflare отдаёт ошибку 1027 до 00:00 UTC.

## D1 (Free)

| Параметр | Лимит | Как учтено |
|---|---|---|
| Строк прочитано | 5 000 000 / сутки | точечные выборки по индексам, пагинация |
| Строк записано | 100 000 / сутки | `fetch_log` не чаще раза в час на человека, проверки батчами |
| Запросов на вызов Worker | 50 | критично: приём проверок ограничен 20 результатами |
| Хранилище | 5 ГБ на аккаунт, 500 МБ на базу | `import_runs` хранит 50 прогонов на источник, `events` чистится вручную |
| Time Travel (PITR) | 7 дней | используется для восстановления |
| Размер строки/значения | 2 МБ | не приближаемся |

После превышения суточных лимитов запросы к D1 начинают возвращать ошибку —
именно поэтому тяжёлые операции разбиты на пачки.

**Фактический случай (23–24.10.2026).** Лимит в 5 млн строк чтения был
исчерпан за сутки: серия проверок туннеля, сканирование статистики по 2000
строк на каждый запрос и диагностические выборки. Последствия: `/sub/*`
отдавал `error code: 1101`, `/api/v1/status` — 500, `/status` показывал
недоступную базу. Лимит сбрасывается в 00:00 UTC.

Что изменено после этого:

- публичные эндпоинты кэшируются в KV (`status` 300 с, `stats` 600 с,
  `sources` 900 с, `servers` 300 с) — чтения D1 больше не повторяются на
  каждый запрос;
- `/sub/*` и `/api/v1/*` при ошибке D1 отдают понятную заглушку и `503`
  с кодом `db_unavailable` вместо 1101;
- квота чтения — главный ограничитель, а не количество запросов: один
  `SELECT` по 1000 строк стоит 1000 строк квоты.

## Workers KV (Free)

| Параметр | Лимит | Как учтено |
|---|---|---|
| Чтения | 100 000 / сутки | одно чтение на запрос подписки |
| Записи в разные ключи | 1 000 / сутки | подписка пишется при промахе кэша, источник — раз в 6 ч |
| Записи в один ключ | 1 / секунда | ключ один на пользователя, TTL 600 с |
| Хранилище | 1 ГБ | мелкие JSON |

При 100 активных подписках и обновлении раз в 10 минут худший случай —
≈ 14 400 записей в сутки, что **выше** лимита. Поэтому:

- `SUB_CACHE_TTL` = 600 с, запись только при промахе;
- при росте аудитории увеличьте TTL до 1800–3600 с;
- при 300+ подписках кэш стоит отключить совсем (читать из D1 дешевле, чем
  упираться в лимит записей KV).

Это честное ограничение архитектуры, а не «бесконечный бесплатный тариф».

## GitHub Actions

| Параметр | Значение |
|---|---|
| Публичный репозиторий | бесплатные минуты не ограничены |
| Приватный репозиторий | 2 000 минут в месяц на Free |
| Один прогон агента | ~10–20 минут на 40 узлов |

Агент проверки — единственный компонент, которому нужен внешний раннер.
Альтернативы: локальный запуск на своём ПК (см. OPERATIONS.md), любой
бесплатный CI, Raspberry Pi.

## Что будет при исчерпании лимитов

| Лимит | Поведение | Что делать |
|---|---|---|
| Workers 100k/сутки | ошибка 1027 | поднять TTL кэша, отключить тяжёлые страницы |
| D1 записи | ошибки записи, чтение может продолжать работать | снизить частоту проверок, почистить `events`/`import_runs` |
| D1 чтения | ошибки запросов | увеличить TTL, уменьшить размер страниц админки |
| KV записи | подписки перестают кэшироваться, читаются из D1 | увеличить TTL или отключить кэш |
| GitHub Actions минуты | workflow не запускается | локальный прогон агента |

## Запасные варианты

- **Хостинг**: Deno Deploy, Vercel Functions, Netlify Functions — требуют
  переписывания слоя D1 на другой драйвер; домен и маршруты сохраняются.
- **База**: Neon / Supabase free tier (карта не нужна) — SQL совместим почти
  полностью, отличается API драйвера.
- **Проверки**: локальный ПК, Raspberry Pi, любой CI с Docker.
- **Кэш**: отключается переменной, KV не является обязательным для работы.

Ни один из запасных вариантов не входит в обязательные зависимости.
