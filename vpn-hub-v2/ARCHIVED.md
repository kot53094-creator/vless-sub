# Архив: VPN Hub v2

**Статус: не развивается.** Код оставлен как исторический материал и как
источник идей; рабочая система — [`../vpn-hub-lite/`](../vpn-hub-lite/README.md).

## Что это было

Отдельное приложение на Python:

- FastAPI + SQLAlchemy + Alembic, PostgreSQL;
- собственный веб-интерфейс с входом по паролю (argon2);
- интеграция с Remnawave для раздела «Люди» и пробных периодов;
- Telegram-бот и планировщик внутри процесса;
- запуск через Docker Compose + Caddy.

## Почему заменено

| Требование | v2 | vpn-hub-lite |
|---|---|---|
| Бесплатный хостинг без карты | нужен VPS/контейнер и Postgres | Cloudflare Workers + D1 + KV |
| Нет отдельного сервера | Docker Compose на машине | один Worker |
| Простое восстановление | дамп Postgres + тома Docker | JSON в Telegram + SQL-экспорт D1 |
| Платные зависимости | Remnawave/Postgres по желанию | нет обязательных платных сервисов |

Плюс v2 требовал держать включённым собственный сервер, а у проекта не было
такой инфраструктуры. Lite повторяет нужную функциональность на бесплатном
плане Cloudflare.

## Что здесь можно переиспользовать

- модели людей и подписок — как ориентир при чтении `docs/SCHEMA.md`;
- тексты бота и сценарии пробного периода;
- идеи разделения «Источники» и «Люди».

## Как запустить (если очень нужно)

```bash
cd vpn-hub-v2
cp .env.example .env
docker compose up --build
```

Понадобятся PostgreSQL и, для модуля «Люди», доступ к Remnawave. Секреты в
`.env` не коммитятся; `.env.example` содержит только имена переменных.

## Перенос данных

Автоматического переноса из v2 в lite нет: разные схемы и разная модель
доступа. Если данные v2 нужны, их выгружают из Postgres и раскладывают в
таблицы `users` / `sources` / `servers` вручную по описанию из
[`../vpn-hub-lite/docs/SCHEMA.md`](../vpn-hub-lite/docs/SCHEMA.md).
