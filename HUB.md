# VPN Hub

Личный дашборд и скрипты для управления VPN-ключами. Разворачивается рядом с
существующей сборкой подписки (`scripts/`, `docs/`) и переиспользует её парсер:
VLESS (Reality, XHTTP, mlkem-шифрование), VMess, Trojan, Shadowsocks.

## Что уже работает (этап 1)

- **Источники** — таблица `sources`: имя, тип (`own_vps` / `trial` / `public` /
  `bridge_ru` / `cdn_xhttp`), ссылка или одиночный ключ, срок, лимит, статус.
- **Добавить ключ** — вставляете `vless://`, `ss://`, `hysteria2://` или ссылку
  подписки; хаб проверяет её до сохранения (TCP + TLS) и только потом пишет в БД.
- **hub-sync** — скачивает подписки с UA Happ, читает `subscription-userinfo`,
  парсит ссылки, дедуплицирует по отпечатку, проверяет порты и TLS в 3 попытки,
  помечает мёртвое, пересобирает выдачу. Лог — потоком SSE.
- **Итоговая подписка** — `/sub/<токен>`, base64 в формате Happ, с заголовками
  `subscription-userinfo` и `profile-update-interval`.
- **Режимы сети** — обычный (`own_vps → trial → public`) и «белые списки»
  (`bridge_ru → cdn_xhttp → own_vps → trial → public`), переключаются вручную.
- **Главная** — режим, живые узлы, трафик, что скоро кончится, последние события.
- **Автозапуск** — пересборка раз в `HUB_SYNC_INTERVAL_HOURS` (по умолчанию 6 ч).

Публичные источники в выдаче помечаются тегом «не для банков».

## Запуск на своём VPS (7 шагов)

```bash
# 1. код на сервер
git clone https://github.com/kot53094-creator/vless-sub.git && cd vless-sub

# 2. секреты
cp .env.example .env
python3 -c "import secrets;print('HUB_SECRET_KEY='+secrets.token_urlsafe(48))" >> .env
python3 -c "import secrets;print('HUB_SUB_TOKEN='+secrets.token_urlsafe(24))" >> .env
# впишите HUB_ADMIN_PASSWORD и HUB_PUBLIC_URL

# 3. домен: A-запись на IP сервера, затем в Caddyfile заменить hub.example.com
nano Caddyfile

# 4. поднять
docker compose up -d --build

# 5. открыть https://ваш-домен → войти → «Источники» → «Добавить ключ»

# 6. ссылка для Happ — на экране «Настройки»
#    профиль правил — «Маршрутизация» → ссылка на JSON

# 7. автозапуск раз в 6 часов (по желанию, см. раздел «Автозапуск»)
sudo ./deploy/install-timers.sh /opt/vless-sub
```

Без домена можно проверить локально: `docker compose up hub` и открыть
`http://IP:8000` (в Caddyfile есть закомментированный блок для IP).

## Проверка после запуска

```bash
curl -s https://hub.example.com/healthz                    # ok
curl -s -o /dev/null -w "%{http_code}\n" https://hub.example.com/login   # 200
curl -s https://hub.example.com/sub/<HUB_SUB_TOKEN> | head -c 120       # base64
curl -s https://hub.example.com/sub/<HUB_SUB_TOKEN> | base64 -d | head  # ссылки
curl -s https://hub.example.com/sub/<HUB_SUB_TOKEN>/routing             # JSON правил
curl -sD - -o /dev/null https://hub.example.com/sub/<HUB_SUB_TOKEN> | grep -i subscription-userinfo
```

Локально, без домена и Docker:

```bash
python -m pytest tests -q                          # 44 passed
HUB_DATA_DIR=./data python -m hub.cli status       # сводка по базе
HUB_DATA_DIR=./data python -m hub.cli routing      # JSON маршрутизации
```

В браузере: «Главная» → «Синхронизация» → «Запустить» → в логе видно каждый
источник, число узлов и итог. После прогона на главной меняются счётчики.

## Этап 2: Remnawave

- Клиент `hub/services/remnawave.py`: пользователи, трафик, срок, HWID-устройства.
- Экран «Ключи»: прогресс трафика, остаток дней, число устройств, подсветка
  жёлтым при <20% остатка или <7 дней, красным при исчерпании и отключении.
- Карточка ключа: устройства (ОС, модель, первый и последний вход, IP, страна)
  и действия — сброс трафика, перевыпуск ссылки, отключение ключа, удаление
  устройства.
- Если `REMNAWAVE_URL` пуст или панель недоступна, хаб продолжает работать:
  экран объясняет причину, остальные разделы живут.
- Пути API можно переопределить через `REMNAWAVE_PATHS_JSON`, если версия
  панели отличается.

## Этап 3: автоустановка ноды

- **`install-node.sh`** — ставит на чистый Ubuntu 22/24 (Debian 12) Xray
  VLESS+Reality на 443 с реалистичным SNI и сгенерированными x25519/shortId,
  Hysteria2 на UDP-порту с самоподписанным сертификатом, включает ufw только
  для нужных портов и BBR. В конце печатает готовые ссылки маркерами
  `VLESS_LINK=` и `HY2_LINK=`.
- Запуск вручную: `sudo NODE_NAME=de-1 ./install-node.sh`
  (переменные `NODE_PORT`, `HY2_PORT`, `SNI`).
- **Экран «Серверы»**: добавление VPS (IP, пользователь, пароль или ключ,
  провайдер, цена, срок аренды), остаток дней, роль (direct / bridge / cdn),
  кнопка «Установить ноду» с логом.
- SSH-секрет хранится зашифрованным (Fernet, ключ выводится из
  `HUB_SECRET_KEY`) и никогда не печатается в интерфейсе.
- Установка идёт в фоне: страница обновляется сама, статус меняется
  `new → provisioning → active` (или `error` с причиной).
- После успеха ссылки ноды автоматически попадают в «Источники» как `own_vps`,
  то есть сразу участвуют в сборке подписки.

## Этап 4: детектор белых списков и Telegram

- Пробы раз в `HUB_DETECTOR_INTERVAL` (по умолчанию 300 с): российский сайт
  (`HUB_PROBE_RU_URL`, по умолчанию ya.ru) и зарубежный
  (`HUB_PROBE_FOREIGN_URL`, generate_204 от Google).
- Режим «белые списки» включается только после **3 подряд** проверок, где
  российский сайт открывается, а зарубежный нет. Выключается сразу, как только
  зарубежный снова заработал. Ручной переключатель остаётся главнее.
- Экран «Настройки»: текущее состояние обоих проб, серия неудач, время
  последней проверки, кнопка «Проверить сейчас».
- Telegram (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`): итог каждой
  синхронизации, ключи с трафиком ≥80% или сроком ≤3 дней, переключение
  режима, новые устройства на ключах Remnawave.
- Без токена уведомления молча отключаются — хаб работает как обычно.

## Этап 5: маршрутизация для Happ

- Экран **«Маршрутизация»** — список правил: тип совпадения (домен, geosite,
  geoip, IP/CIDR, протокол), значение, выход (`direct` / `main` / `usa` / `eu` /
  `nearest`), порядок и заметка. Правила добавляются, выключаются и удаляются
  без рестарта.
- При первом запуске таблица заполняется семью правилами: российские домены и
  адреса — напрямую, ИИ-сервисы (OpenAI, Anthropic, Gemini, Perplexity,
  Copilot) — через США/ЕС, игры по UDP — через ближайшую ноду (Hysteria2).
  Всё остальное — `final: main`, то есть основной профиль.
- Профиль отдаётся по той же секретной ссылке:
  `https://ваш-домен/sub/<HUB_SUB_TOKEN>/routing` — JSON в формате
  `route.rules` (sing-box). Его понимают Happ, sing-box и nekobox.
- Ссылка на профиль есть на экране, в JSON-превью и в заголовке
  `routing-profile-url` ответа подписки.
- Как подключить: Happ → профиль → **Routing** → импорт правил → вставить
  ссылку или JSON. Теги выходов сопоставляются один раз: `direct` — напрямую,
  `main` — основной профиль, `usa`/`eu` — узлы этих стран, `nearest-udp` —
  ближайшая нода по UDP.

Важно: Happ не тянет routing-правила автоматически вместе с подпиской —
стандартного заголовка для этого нет. Правила импортируются один раз вручную,
дальше меняются на экране «Маршрутизация» и подхватываются при следующем
обновлении JSON.

## Этап 6: метрики, серверы и уведомления

- **Трафик за сутки и месяц.** При каждом прогоне пишется снимок счётчиков
  (`traffic_samples`), расход считается как разница с началом окна. На главной
  две отдельные карточки — 24 часа и 30 дней.
- **История доступности за 7 дней.** Каждая проверка источника пишется в
  `check_events`; на экране «Источники» — семь полосок (зелёная/красная/серая)
  и кнопка **«Проверить сейчас»** для одного источника, без полного прогона.
- Публичные источники помечены значком **«ненадёжный»**, а в подписке —
  тегом «не для банков».
- **Серверы:** поля «нагрузка» и «ссылка на панель провайдера», кнопка
  **«Замерить нагрузку»** (SSH: loadavg и память) и **«Создать на новом
  сервере»** — перенос ноды: новый VPS ставится тем же установщиком, после
  успеха старый источник отключается автоматически.
- **Уведомления:** за 3 дня / 1 день / в день окончания ключа и аренды VPS,
  при 100% трафика, при падении ноды (источник перестал отвечать или нода
  Remnawave ушла в offline), при новом **HWID**-устройстве на ключе,
  при переключении режима и итог каждого hub-sync. Одно и то же
  предупреждение не повторяется чаще раза в сутки (`notifications_sent`).
- **TOTP.** `python -m hub.cli totp-secret` выдаёт секрет и otpauth-ссылку;
  впишите его в `HUB_TOTP_SECRET` — на входе появится поле для кода.
- **Миграции.** Alembic: `alembic upgrade head` выполняется в контейнере перед
  стартом; вручную — `python -m alembic upgrade head`.
- Кнопка **«Обновить всё»** на главной сразу открывает лог и запускает прогон
  (раньше нужно было нажать вторую кнопку).

### Telegram: подключение

1. Впишите `TELEGRAM_BOT_TOKEN` в `.env` и перезапустите хаб.
2. Напишите боту любое сообщение (например `/start`).
3. «Настройки» → **«Проверить бота»**: хаб вызовет `getMe`, заберёт `chat_id`
   из последнего сообщения, сохранит его и отправит тестовое сообщение.

Из России `api.telegram.org` часто недоступен — проверяйте с VPS, где хаб
работает. Если бот не отвечает, кнопка честно покажет ошибку.

## Автозапуск каждые 6 часов: три способа

Выберите **один**, иначе прогоны будут дублироваться.

**1. Встроенный планировщик (по умолчанию).** Работает, пока жив контейнер:
`HUB_SCHEDULER_ENABLED=1` и `HUB_SYNC_INTERVAL_HOURS=6`. Ничего ставить не нужно.

**2. systemd-таймер (переживает рестарты, виден в journalctl).**

```bash
sudo ./deploy/install-timers.sh /opt/vless-sub
# затем выключите встроенный планировщик, чтобы не было двух прогонов:
echo 'HUB_SCHEDULER_ENABLED=0' >> .env && docker compose up -d

systemctl list-timers 'vpnhub-*'
systemctl start vpnhub-sync.service           # проверка вручную
journalctl -u vpnhub-sync -n 50
```

Файлы: `deploy/vpnhub-sync.{service,timer}` (раз в 6 часов),
`deploy/vpnhub-detector.{service,timer}` (детектор раз в 5 минут).

**3. cron.**

```bash
crontab -e     # строки из deploy/crontab.example
```

Файл `deploy/crontab.example` содержит обе задачи и напоминание про
`HUB_SCHEDULER_ENABLED=0`.

Обе службы вызывают одну и ту же команду — её можно запускать и руками:

```bash
docker compose exec -T hub python -m hub.cli sync          # один прогон hub-sync
docker compose exec -T hub python -m hub.cli sync --mode whitelist
docker compose exec -T hub python -m hub.cli detect        # проба белых списков
docker compose exec -T hub python -m hub.cli status        # сводка по базе
docker compose exec -T hub python -m hub.cli routing       # JSON правил
docker compose exec -T hub python -m hub.cli hash-password 'пароль'
```

## Что сделано по этапам

1. Ядро: `sources`, hub-sync, итоговая подписка, главная, режимы сети.
2. Remnawave: ключи, трафик, HWID-устройства, действия с ключом.
3. Автоустановка ноды по SSH + `install-node.sh` для ручного запуска.
4. Детектор белых списков и уведомления в Telegram.
5. Маршрутизация для Happ: правила, экран редактирования, JSON по ссылке.
6. Метрики (трафик за сутки/месяц, история 7 дней), серверы (нагрузка,
   панель, перенос), уведомления по срокам/нодам/устройствам, TOTP, Alembic.
7. Тесты на парсер, проверку ключей, детектор, Remnawave, маршрутизацию,
   метрики, дедлайны и второй фактор.

Осталось на будущее (в ТЗ помечено как опциональное): сценарий XHTTP через
CDN (Xray + nginx) и сценарий моста «российский сервер → зарубежный выход»
отдельной инструкцией.

## Безопасность

- Пароль — argon2 (или готовый хеш в `HUB_ADMIN_PASSWORD_HASH`).
- Сессия — подписанная cookie, HttpOnly; CSRF-токен в отдельной cookie.
- Лимит попыток входа: 8 за 5 минут с одного IP.
- Ссылки в интерфейсе маскируются, в логах ключи не печатаются.
- SSH-секреты серверов хранятся в БД в зашифрованном виде (этап 3).
